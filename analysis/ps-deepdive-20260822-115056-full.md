## 1. SIH26108 — AI-Powered Recommendation Engine for Identifying Applicable Indian Standards for Procurement Specifications

**Organization:** Ministry of Consumer Affairs, Food & Public Distribution · Software · Smart Automation

### 2. Problem Summary
Government departments, PSEs and procurement agencies must write tender technical specifications referencing correct Indian Standards (IS), but the huge number of standards, overlapping scopes, frequent revisions, and normative cross-references make manual identification error-prone (per Background). Result: tenders omit relevant standards, cite outdated versions, or have incomplete requirements, causing disputes. The ask is an engine that reads a product description/spec/tender document and recommends the right IS codes plus allied/normative standards.

### 3. Explicit Requirements (from "Expected Features" in JSON — note: this PS uses "Expected Features" instead of "Expected Solution")
1. Accept product descriptions, technical specifications, or tender documents as input.
2. Recommend most relevant Indian Standard(s) via semantic understanding, explicitly *not* keyword matching.
3. Identify allied standards: normative references, test methods, terminology, safety, installation, related product standards.
4. Highlight latest published version and amendments of recommended standards.
5. Suggest mandatory certification requirements where applicable (BIS Product Certification, CRS, Hallmarking).
6. Support multilingual input and natural language queries.
(Description adds: integrate with procurement portals.)

### 4. Functional Requirements *(derived)*
- **AI/ML:** sentence-embedding semantic retrieval + hybrid BM25 (RAG pattern); LLM for query rewriting/explanations; a certification-mapping layer (product category → mandatory cert scheme); optional cross-reference graph traversal for allied standards.
- **Data sources:** IS catalog metadata (numbers, titles, scopes, versions, amendments, normative refs) — publicly browsable via BIS portals (see §7); certification scheme product lists (BIS CRS/Hallmarking lists).
- **Frontend:** multilingual NL query box, ranked results with version/amendment badges and cert flags, document view.
- **Backend:** catalog ingestion pipeline, vector index + keyword index, recommendation API, portal-integration stub API.

### 5. Non-Functional Requirements
- Multilingual support — explicit in text.
- Semantic accuracy bar ("not keyword matching") — explicit.
- Portal integration capability — mentioned in Description.
- Offline capability / scalability / data privacy: **not mentioned in PS text.**

### 6. Data Dependency Check — **CACHE-FRIENDLY**
Core demo = retrieval over a pre-loaded snapshot of the IS catalog. No government feed needs to be live during judging: BIS's own public tools are keyword lookup only (verified below), so nothing in the demo depends on a live API. An offline/local LLM removes even the last network dependency. **Verdict: fully cacheable; R3-safe.**

### 7. Existing Solutions Check
- **Official (primary):** BIS "Know Your Standard" (bis.gov.in) — search by IS number or keyword; returns PDFs, amendments, gazette notifications, licenses. Keyword lookup, **no semantic/allied-standard recommendation**. BIS Connect endpoint exists at services.bis.gov.in for standard details. MANAK Online (manakonline.in) covers license/product-standard search per BIS FAQ.
- **Commercial:** ISCode.ai (iscodesearch.com) — natural-language IS code Q&A, focused on civil/structural codes (IS 456, IS 800 etc.), grounded answers with clause references, multilingual claim.
- **Hackathon prior art [community — GitHub/git hosting, unverified quality]:** SpecForge (git.kska.io/notkshitij/SpecForge) and BIS-COMPASS (github.com/SaudSatopay/BIS-COMPASS) — both RAG engines over BIS SP-21 (929-page building-materials summaries, ~560–590 standards), FAISS+BM25 hybrid, anti-hallucination whitelist. These prove the architecture wins hackathons but cover only building materials.
- **Differentiation for us:** full-catalog coverage beyond SP-21 (~23,700 standards exist per SESEI report, sesei.eu), allied/normative cross-reference chains, latest-version/amendment surfacing from official BIS data, certification mapping (CRS/Hallmarking), multilingual queries — none of the found tools do all five.

### 8. Winnability Score — **4/5**
Pure-software RAG build that matches our ML/full-stack stack exactly, runs fully on cached data, and is proven feasible in hackathon timeframes — docked one point because assembling a quality full-catalog dataset with version/amendment metadata inside 36h is real work and recommendation correctness is hard for judges to verify quickly.

### 9. Red Flags

- Multilingual expectation adds surface area.

### 9. Red Flags

## 4. SIH26092 — AI-Driven Scheme Matching for Marginalized Entrepreneurs

**Organization:** Ministry of Social Justice and Empowerment (MoSJE) · Software · Miscellaneous

### 2. Problem Summary
SC beneficiaries (family income up to ₹5 lakh) can get concessional credit covering up to 90% of project/education costs at 6.5–8% p.a., but applications are never taken directly — funds flow through a Channel Finance System of 100+ partners (SCAs, PSBs, RRBs, NBFC-MFIs) (Background). Ask: intelligent, multilingual platform bridging beneficiaries and channelizing agencies.

### 3. Explicit Requirements (verbatim-derived from Expected Solution)
1. **Smart Scheme Recommender:** AI/rule-based engine taking user inputs (project type, estimated cost, income level, education status) → recommends most suitable credit/educational-loan scheme.
2. **Financial Calculator:** dynamic EMI projection honoring scheme guidelines — max loan limits, interest rates (6.5%–15% depending on scheme), moratorium periods (3–12 months).
3. **Geo-Spatial Partner Locator & Router:** mapping-service integration to find nearest eligible Channel Partner (SCA/Bank/NBFC-MFI) based on user location AND the partner's fund-utilization eligibility (avoid routing to partners with high NPAs/overdues).

### 4. Functional Requirements *(derived)*
- **AI/ML:** honestly minimal — rule engine + optional LLM conversational front-end/multilingual chat; classification is deterministic from published tiers. (A small intent-classifier for free-text business descriptions is defensible.)
- **Data sources:** NSFDC scheme parameters (published tables, verified — see §7); channel-partner directory with geocoded addresses (NSFDC publishes SCA/co-op/other/PSB lists as PDFs/pages); map tiles via any provider (OSM works offline-ish/cached).
- **Frontend:** multilingual wizard (inputs → scheme → EMI schedule → nearest partners on map).
- **Backend:** rules engine, amortization calculator, partner-directory DB + haversine/routing, eligibility filter stub.

### 5. Non-Functional Requirements

No live government feed required at any point. Partner "fund-utilization eligibility" has no public feed — modeled as a demo dataset attribute, which the PS implicitly accepts by asking us to design for it. **Verdict: 100% pre-loadable; lowest R3 risk of all six.**

### 7. Existing Solutions Check

We're building the missing pre-application guidance layer between myScheme (discovery) and PM-SURAJ (application).
