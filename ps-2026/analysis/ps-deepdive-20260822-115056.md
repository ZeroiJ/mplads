## 🥇 SIH26102 — MPLADS Anomaly/Fraud Detection · MoSPI
**The problem:** Mine MPLADS sanctions/expenditure/progress/payment data to flag unusual patterns, cost overruns, duplicate works and delays → risk alerts + dashboards for MPs/Districts/States/Ministry.

**Build:** Isolation Forest / cost-norm anomaly detection, duplicate-work detection (text similarity + geo + amount), simple delay prediction, rule-based compliance flags. Frontend: analyst dashboard + role filters. Backend: ingestion pipeline + alert rules.

**Data:** ✅ CACHE-FRIENDLY, **best of all six** — works/expenditure data is public and bulk-downloadable (mplads.gov.in per-work tables; eSAKSHI covers Apr 2023+; `[community]` GitHub CSV mirror Vonter/india-mplads-works as accelerator).

**Competition:** Official portals (mplads.gov.in dashboard, eSAKSHI, GIS) are descriptive-only — no AI layer found anywhere. Academic studies exist (EPW 2010 political cycles; Keefer & Khemani 2008; PEO/CAG inflated-spending findings; JETIR 2026) — great intuition for what anomalies to look for, but **no deployed tool found**.

**Why 5/5:** Real abundant public data + textbook unsupervised ML + full-stack dashboards = exactly our skillset, zero hardware, zero live-feed risk.
**Watch out:** Don't build all four role dashboards (one view + filters); frame flags as "risk indicators for human review," never accusations; eSAKSHI-era vs legacy data schemas differ; curate duplicate-detection showcase cases to avoid false-positive embarrassment.

## 🥈 SIH26092 — Scheme Matching for Marginalized Entrepreneurs · MoSJE
**The problem:** SC beneficiaries (income ≤₹5L) get 90% concessional credit via 100+ channel partners, but don't know which scheme fits or where the nearest eligible partner is → misrouted applications.

**Build (3 modules straight from PS):** ① scheme recommender from inputs (project type/cost/income/education), ② EMI calculator honoring limits/rates/moratoriums, ③ geo locator routing to nearest partner filtered by fund-utilization eligibility. Rules engine + map UI; AI depth is thin by design — add a grounded multilingual chat layer.

**Data:** ✅ CACHE-FRIENDLY, **safest of the six** — every parameter is in the PS itself; NSFDC's site publishes exact tier tables (Micro ≤₹1.40L→₹1.25L @6.5%, etc.) and partner lists as PDFs; maps cacheable.

**Competition:** myScheme.gov.in = generic discovery only (no calculators/routing); PM-SURAJ = application portal only; Jan Samarth = generic loan checker. Nothing combines tier-exact structuring + geo-routing → we're the missing pre-application guidance layer between myScheme and PM-SURAJ.
⚠️ Data note: NSFDC pages conflict on income ceiling (₹3L w.e.f. 2018 vs ₹5L effective Jan 2026) — PS uses ₹5L, matches newer figure.

**Why 5/5:** Fully specified rules verified against live official sources; deterministic outputs judges can instantly verify.
**Watch out:** Rehearse the "myScheme already exists" answer; partner NPA data isn't public (present as designed-for); stick to responsive PWA despite "mobile app" phrasing.

## 🥉 SIH26103 — PAIMANA Predictive Early Warning · MoSPI
**The problem:** PAIMANA tracks 1,981 infra projects ≥₹150cr (~₹42.78 lakh crore revised cost). Monitoring is descriptive; build an open-source ML system predicting cost/time overruns and risks before they happen.

**Build:** Pick a subset of the outcomes menu (a–i): risk-scoring framework + early-warning alerts + dashboard (+ driver analysis). Gradient boosting vs statistical baseline (the PS *demands* this comparison). Optional LLM assistant over project records.

**Data:** ✅ CACHE-FRIENDLY — train on pre-loaded historical snapshot, demo replays locally. Public dashboard shows aggregates only; granular CUF-field history likely needs organizer-provided extracts → budget dataset effort. Portal is beta with migration caveats (official stats still at cspm.gov.in).

**Competition:** Key finding: NIC article says AI-driven overrun forecasting is PAIMANA's **future roadmap — not built yet**. We'd prototype the ministry's stated plan. No deployed public prediction tool found.

**Why 4/5:** Open-source mandate + pick-your-outcomes menu fits our data-eng+ML team perfectly; held back only by uncertain granular training-data access.
**Watch out:** Menu is huge (a–i) — self-scope ruthlessly; hand-wavy dashboards will fail the baseline-vs-ML rigor bar.

## 4️⃣ SIH26108 — Indian Standards Recommendation Engine · Ministry of Consumer Affairs
**The problem:** Procurement officials writing tender specs cite wrong/outdated/incomplete IS codes. Build an engine that reads a product description/tender doc → recommends right IS codes + allied/normative standards, latest versions/amendments, certification flags (BIS/CRS/Hallmarking), multilingual NL queries.

**Build:** RAG (embeddings + BM25 hybrid), LLM explanations, certification-mapping layer, version/amendment surfacing. Pre-loaded IS catalog snapshot is the whole demo.

**Data:** ✅ CACHE-FRIENDLY — retrieval over cached BIS catalog; BIS's own tools are keyword-only lookup so nothing live is needed.

**Competition:** Official BIS "Know Your Standard" = keyword lookup, no semantics. Commercial ISCode.ai = civil codes Q&A. Two `[community]` hackathon RAG prototypes exist over BIS SP-21 building materials only (~580 standards): SpecForge, BIS-COMPASS. Differentiate via: full catalog (~23,700 standards per SESEI report), cross-reference chains, version tracking, cert mapping, multilingual.

**Why 4/5:** Proven architecture, perfect stack fit, cache-safe — docked for assembling a quality full-catalog dataset in 36h + fuzzy ground truth.
**Watch out:** BIS-expert judges will probe niche standards; two existing clones = me-too risk unless differentiation is loud.

## 5️⃣ SIH26091 — Rural Business Advisory Assistant · MoSJE
**The problem:** First-time rural entrepreneurs pick businesses on anecdote and can't structure loans. Build: Module 1 = village-level feasibility report (market reach 5–10km, niches, SWOT, threats, competitor density, pricing); Module 2 = deterministic calculator (Margin÷10% = project cost; 90% loan; auto-scheme: ≤₹1.40L→Micro @6.5%/3yr, >₹1.40L≤₹50L→Term @8%/7yr; EMI schedule). Multilingual NLP assistant.

**Build:** LLM advisory grounded on pre-loaded Census village slices + template report gen; Module 2 is pure arithmetic. Census data bulk-downloadable; no API gives true Gram-Panchayat market saturation → census proxies + clearly-labeled estimates.

**Data:** ⚠️ CACHE-FRIENDLY but weakest grounding — Module 1's substance (competitor density, purchasing power) has no authoritative public source; private platforms literally sell this gap.

**Competition:** Most crowded of the six: Vyapar Mitra (NGO voice assistant), Business Roadmap (paid AI feasibility + DPRs), Shunya VAR (free census+geo radius viability reports — proves methodology), LightHouse (paid rural intelligence), NariBot/Meri Saheli/BizChat. No govt tool found. Differentiation: fuse feasibility + MoSJE scheme-router math in one free multilingual flow.

**Why 3/5:** Module 2 trivial, but Module 1 = six fuzzy deliverables on thin data in a crowded space — highest "LLM wrapper" risk if under-engineered.
**Watch out:** Scope creep built into Module 1; PS has arithmetic typos ("₹10,00,00") — source values from NSFDC tables, not PS literals.

## 6️⃣ SIH26099 — CPSE Material Code Harmonization · Ministry of Petroleum & Natural Gas
**The problem:** Same material, different codes/descriptions/UoM across CPSEs → duplicate masters, fragmented procurement. Build AI matching platform issuing a Common National Material Code while keeping legacy mappings ("One Nation – One Material Code").

**Build:** Entity resolution (embeddings + fuzzy match), classification onto UNSPSC-style taxonomy, code generator + mapping store, review/approve workflow, analytics dashboard, audit trail. **No public data exists** — demo runs entirely on synthetic multi-ERP CSV extracts.

**Data:** ⚠️ CACHE-FRIENDLY by necessity — zero live-feed risk, but also zero real-world validation; credibility rests fully on synthetic data realism.

**Competition:** GeM uses UNSPSC for marketplace categories (not CPSE internal masters); defence NATO Codification System (NSN, "One Item One Code", ~36M items) is the closest operational analogue but defence-scoped; "One Nation One Standard" is unrelated policy branding. **No CPSE-level platform found** — first-mover position, no validation surface.

**Why 3/5:** Clean entity-resolution problem in our wheelhouse, killed by synthetic-only demo + enterprise scope creep.
**Watch out:** Explicit SAP/ERP integration + legacy migration + audit/governance expectations are classic hackathon scope creep; judges will ask "does it work on real CPSE data?" — unanswerable.
